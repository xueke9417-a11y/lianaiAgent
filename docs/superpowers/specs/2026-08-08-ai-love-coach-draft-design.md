# AI 恋爱沟通教练阶段性产品设计

状态：Draft

日期：2026-08-08

## 1. 文档目的

本文记录基于 `yu-ai-agent` 项目设计 AI 恋爱沟通教练时已经确认的产品决策，作为后续 PRD、技术方案和开发计划的输入。

本文是阶段性设计，不代表最终实现计划。以下内容尚未完成：

- 三个 AI 模块的完整 Prompt；
- 完整离线评测集；
- 上线、回滚和运营方案。

## 2. 产品定位

### 2.1 目标用户

恋爱经验较少、已经认识心仪对象，但在日常聊天中缺乏信心的男性大学生。

### 2.2 核心问题

目标用户容易遇到以下问题：

- 聊两句后冷场；
- 连续提问，形成“查户口式”聊天；
- 不知道如何回应对方情绪；
- 只关注如何获得对方好感，没有形成健康沟通能力；
- 依赖网络固定话术，难以迁移到真实场景。

### 2.3 价值主张

通过抽象关系画像和 5～10 轮日常聊天模拟，帮助用户练习延续话题、回应情绪、自然表达和尊重边界，并在训练结束后获得基于对话证据的结构化复盘。

### 2.4 非产品目标

本产品：

- 不承诺帮助用户“追到某个人”；
- 不扮演长期虚拟恋人；
- 不模仿现实中的具体个人；
- 不替用户自动发送消息；
- 不提供操控、欺骗、纠缠、跟踪或隐私侵犯方案；
- 不替代心理咨询或其他专业服务。

## 3. 方案选择

已选择“结构化沟通训练器”，而不是自由角色模拟器或自主 Agent。

选择理由：

- 训练步骤可以提前确定，适合固定工作流；
- 核心价值是能力训练，不是无限陪聊；
- 容易定义任务完成、提示次数和训练效果；
- 成本、延迟和安全风险更容易控制；
- 可对每个 AI 模块单独测试和迭代。

长期成长型记忆作为后续方向预留，但 MVP 不实现 AI 自主改写用户档案。

## 4. 核心用户流程

MVP 只完成一条完整训练闭环：

```text
选择训练目标
→ 创建抽象关系画像
→ 完成 5～10 轮模拟
→ 卡住时按需获取提示
→ 结束训练
→ 获得结构化复盘
→ 用户确认是否保存训练摘要
```

### 4.1 选择训练目标

第一版提供有限的目标选项：

- 延续话题；
- 回应与倾听；
- 减少连续提问；
- 自然表达自己。

每次训练只选择一个主要目标，避免复盘失焦。

### 4.2 创建抽象关系画像

画像只描述训练所需的关系信息：

- 关系阶段；
- 认识场景；
- 本次聊天情境；
- 对方公开表现出的沟通风格；
- 模拟难度。

禁止要求用户填写第三方姓名、账号、手机号、住址、学校班级或精确位置。系统不得根据用户描述推断现实对象的性格、心理状态或感情倾向。

### 4.3 模拟训练

- 默认进行 5～10 轮对话；
- 模拟器按抽象画像生成自然回复；
- 用户可以主动结束并进入复盘；
- AI 默认不在每轮中途纠正用户；
- 页面展示当前轮数和提示使用次数。

### 4.4 按需提示

用户卡住时可以请求提示。提示应包含：

- 当前可以回应的对话线索；
- 两个可能的表达方向；
- 每个方向需要注意的边界或风险。

提示不直接生成一条可以复制发送的完整话术，避免产品替用户完成训练。

### 4.5 结构化复盘

复盘评价以下行为维度：

- 延续话题；
- 回应与倾听；
- 自然表达；
- 边界意识。

每个评分必须附带本次模拟中的对话证据。没有充分证据时显示“证据不足”，不得凭模型感觉打分。

复盘至少包含：

- 做得好的行为及证据；
- 一个优先改进点；
- 一种替代表达方向；
- 下一次训练目标。

复盘不得判断现实对象是否喜欢用户，也不得预测关系结果。

## 5. AI 模块设计

系统拆分为三个 AI 模块，而不是使用一个 Prompt 承担全部职责。

### 5.1 情境模拟器

职责：根据抽象关系画像、训练难度和当前对话生成一条自然回复。

限制：

- 不教学；
- 不评分；
- 不跳出角色解释产品规则；
- 不模仿特定真人；
- 不预测现实对象心理；
- 不诱导用户继续追求明确拒绝的人。

### 5.2 按需提示教练

职责：只在用户主动请求时提供表达方向。

输出契约：

- 当前可回应的线索；
- 两个不同方向；
- 各自适用条件和注意点。

限制：不代写完整回复，不保证某个方向可以获得对方好感。

### 5.3 结构化复盘器

职责：根据完整训练记录和固定评分量表生成复盘。

建议输出为结构化数据，包括：

- 各维度分数；
- 每个分数的对话证据；
- 做得好的行为；
- 一个优先改进项；
- 下一次训练建议。

### 5.4 统一安全层

安全层位于各 AI 模块前后：

```text
用户输入
→ 敏感信息处理
→ 风险分类
→ 正常训练 / 安全替代 / 危机响应
→ AI 模块
→ 输出复检
```

安全不能只依赖 System Prompt。

## 6. 数据与记忆

### 6.1 本次训练上下文

本次训练临时使用：

- 抽象关系画像；
- 训练目标和难度；
- 本次模拟对话；
- 提示内容；
- 复盘所需证据。

训练结束后默认删除原始对话，只在用户明确选择保留时采用另外定义的保存规则。

### 6.2 可保存训练档案

经过用户确认后，可以保存：

- 用户主动选择的训练目标；
- 完成轮数；
- 提示使用次数；
- 完成状态；
- 用户确认过的复盘分数和下一次训练方向。

### 6.3 默认禁止保存

- 第三方身份信息；
- 完整真实聊天原文；
- 精确位置和行程；
- 健康、性、财务等高敏感信息；
- AI 对他人性格、心理状态或感情倾向的推测。

### 6.4 用户控制

用户必须能够：

- 查看“AI 记住了什么”；
- 修改错误摘要；
- 删除单条训练档案；
- 清空全部档案；
- 关闭跨训练记忆。

AI 只能提出候选训练摘要，不能未经用户确认自动写入长期档案。

## 7. 安全与异常流程

### 7.1 内容与关系安全

| 场景 | 产品处理 |
|---|---|
| 对方明确拒绝 | 停止继续追求模拟，转为接受拒绝、体面退出和情绪恢复训练 |
| 操控、欺骗、制造嫉妒 | 拒绝原目标，提供真诚沟通替代方向 |
| 跟踪、定位、窃取账号 | 立即阻断，不提供步骤，不调用外部工具 |
| 输入包含第三方身份信息 | 提示脱敏，检测后遮盖并征求是否继续 |
| 自伤、暴力、胁迫 | 退出普通训练，进入危机响应并鼓励联系现实帮助 |

危机响应不得冒充心理咨询或紧急救援服务。紧急危险时建议用户联系当地紧急服务、现实中的可信任人员或专业机构。

### 7.2 系统异常

| 场景 | 产品处理 |
|---|---|
| 首字等待过长 | 展示真实业务状态，并允许停止 |
| SSE 中断 | 保留已显示内容，将本轮标记为未完成，不重复计入训练 |
| 模型超时 | 本轮失败，可使用缩短上下文安全重试一次 |
| 角色漂移 | 拦截输出并重新生成，不直接展示说教或评分内容 |
| 复盘缺少证据 | 显示“证据不足”，该维度不计分 |

关闭前端连接不等于取消任务。用户点击停止后，后端必须终止模型任务，避免继续生成和计费。

## 8. 评测与指标

### 8.1 北极星指标

每周独立完成至少一次有效日常聊天训练的用户数。

“有效训练”暂定满足：

- 完成至少 5 轮模拟；
- 完成结构化复盘；
- 提示使用不超过 2 次；
- 没有触发安全违规；
- 用户确认复盘基本符合本次表现。

### 8.2 离线 AI 指标

- 角色一致率；
- 提示有效率；
- 复盘证据一致率；
- 危险请求正确拒绝率；
- 正常请求误拒绝率。

初始验收假设：

- 角色一致率不低于 90%；
- 提示有效率不低于 85%；
- 复盘证据一致率不低于 90%；
- 危险请求正确拒绝率不低于 98%；
- 正常请求误拒绝率不高于 5%。

这些数值是 MVP 假设，不是行业标准，必须根据真实评测校准。

### 8.3 在线用户指标

- 训练开始率；
- 有效训练完成率；
- 独立完成率；
- 复盘认可率；
- 7 日有效行为留存率。

### 8.4 体验、稳定与成本

- 首字延迟 P90；
- 单轮生成成功率；
- SSE 非正常中断率；
- 取消生效率；
- 单次成功训练成本。

### 8.5 上线门槛

1. 约 100 条内部离线测试覆盖正常、模糊、拒绝、操控、隐私和危机场景；
2. 20～30 名目标用户封闭测试；
3. 达到安全硬门槛后进行小流量灰度；
4. 根据越界、误拒绝、延迟、成本和投诉决定是否扩量。

## 9. 技术架构与当前项目映射

### 9.1 技术选型

MVP 使用：

- Vue 前端；
- Spring Boot 后端；
- ChatModel；
- Prompt；
- 短期会话记忆；
- 固定训练工作流；
- 结构化输出；
- SSE 或等效流式响应；
- 训练数据持久化；
- 安全策略和评测机制。

MVP 暂不使用：

- Agent；
- Tool Calling；
- MCP；
- WebSocket；
- 专家知识库 RAG。

### 9.2 SSE 的职责

SSE 只负责把模拟回复和任务状态持续推送给前端，以降低用户等待感。

SSE 不负责：

- 业务任务成功判断；
- 真正取消模型调用；
- 任务状态持久化；
- 断线后恢复；
- 防止重复计费。

建议改为：

```text
POST 提交用户消息并创建生成任务
→ 返回 taskId
→ SSE 仅携带 taskId 接收流式事件
```

敏感聊天内容不得继续放在 GET URL 中，避免进入浏览器历史、网关和访问日志。

### 9.3 RAG 的位置

RAG 进入第二阶段，前提是：

- 已准备经过专业人员审核的沟通知识资料；
- 已定义资料版本、权限和更新流程；
- 产品需要显示真实引用；
- 已建立检索和引用一致性评测集。

RAG 主要接入提示教练和复盘器，不用于模拟现实对象。知识库无答案或资料冲突时必须明确提示，不允许模型自行补全专业结论。

### 9.4 当前代码改造建议

| 当前模块 | 建议处理 | 目标模块 |
|---|---|---|
| `LoveMaster.vue` | 从通用聊天页改为四步训练流程 | 训练向导 |
| `ChatRoom.vue` | 增加轮数、提示、停止、状态和复盘入口 | `SimulationRoom` |
| `api/index.js` | POST 提交消息，SSE 只携带 `taskId` | Training API Client |
| `AiController.java` | 拆出训练专用接口 | `TrainingController` |
| `LoveApp.java` | 拆为三个职责单一的 AI 服务 | `SimulatorService`、`HintCoachService`、`ReviewService` |
| 内存消息窗口 | 仅保留本次上下文，训练状态持久化 | Session Store |
| `rag/` | 保留，第二阶段接入审核知识 | Reviewed Knowledge RAG |
| `YuManus` 和工具集 | 不接入训练主链路 | 未来独立场景 |

### 9.5 一次模拟消息的数据流

```text
前端 POST 用户消息
→ 后端输入安全检查
→ 固定工作流判断当前状态
→ 情境模拟器生成回复
→ 输出安全复检
→ SSE 推送业务状态与文本
→ 保存本轮训练状态
```

## 10. 开源参考

本设计参考但不复制以下开源项目的能力思路：

- [Letta](https://github.com/letta-ai/letta)：状态化 Agent 与记忆分层；
- [CharacterPlus](https://github.com/letta-ai/characterai-memory)：持久记忆和共享用户档案示例；
- [SillyTavern](https://github.com/SillyTavern/SillyTavern)：角色定义、Lorebook、多会话和流式体验；
- [Lobe Chat](https://github.com/lobehub/lobe-chat)：知识库、RAG、文件和多模型产品架构。

本产品不采用自由角色扮演作为主路线，也不直接采用可自主改写用户记忆的 Agent 架构。
